# 网站管家第一版

管理员已完成 ChatGPT/Codex 账号授权，真实模型连接及受限执行环境验证通过。后台与独立控制器已上线；真实模型修改、基线与候选测试、浏览器和发布保护验证通过。

## 组成

- 现有后台增加“网站管家”：任务消息、执行进度、运行诊断、代码差异和测试结果、发布及回滚记录。
- 独立 systemd 管家服务管理持久任务队列。关闭网页后任务继续；网站和旅游各一个任务名额，可同时运行。
- Codex CLI 使用独立 Linux 账号和开发副本；不复用 root 的配置、插件、认证或会话。
- PostgreSQL 保存任务与消息，纳入现有备份；原有攻略和足迹表不改写。
- 模型运行、测试、发布分开：模型只写开发副本，测试在独立库中进行，发布读取停止模型进程后生成的固定候选版本。

## 执行边界

- 普通巡检复用现有 systemd 定时检查，模型仅在收到任务时调用。
- 模型和生成的代码不以 root 执行，不授予 sudo，不读取生产密码或会话密钥。
- 网页只调用固定的管家操作，不提供任意 root shell。
- 自动发布校验候选代码摘要、基线版本和测试结果；生产已变化时拒绝覆盖。
- schema、依赖和系统运维配置变化进入单独迁移流程。
- 第一版变更预览以代码差异、检查结果为准，截图可作为附件；不把未审核的网页脚本放进有管理员登录态的同源预览页。

## 模型接入：账号登录

使用管理员在官方页面授权的 ChatGPT/Codex 账号。独立系统用户为 `travelagent`，认证目录为 `/var/lib/travel-agent/home/.codex`，目录权限 0700。不能复用 root 的登录凭据或环境变量。

管理员通过 SSH 执行 `travel-agent-auth login` 发起设备码登录，`travel-agent-auth status` 查看状态。若设备码不可用，可使用 `travel-agent-auth browser-login` 配合 SSH 转发 localhost:1455。认证令牌不写进项目、不显示在网页、不通过聊天传递。禁止自动切换到 API 计费。

已确认本机 Codex CLI 0.155.1 提供 `exec --json`、`--sandbox workspace-write`、`--ignore-user-config`、`--skip-git-repo-check`。已完成真实模型调用、隔离目录写入与权限验证。

参考：[Codex 非交互运行](https://learn.chatgpt.com/docs/non-interactive-mode)、[身份验证](https://learn.chatgpt.com/docs/auth)。
## 旅游研究任务

旅游助手使用独立执行名额的持久队列，以 `request.assistant=travel` 和 `kind=chat` 标记。`travel_planner.py` 提供专用指令、响应 Schema 和严格输出校验；`service.py` 对此分支创建空工作目录，启用 live web search、禁用 shell/apps，使用 read-only 沙箱，不复制项目、不提供运维上下文、不调用测试或发布。

任务结果将完整攻略写入 `report.travel_guide`，正文写入 `result`，实际检索次数写入 `report.web_search_count`。存档由管理员显式点击后通过网站受保护 API 完成，固定先存草稿；模型没有生产写入工具。历史上下文仅串接同类旅游任务。两个后台入口在 API 层分离，不允许跨类型关联、取消或发布。

## 两队列与图文攻略
控制器保持单线程、网站/旅游各 1 个子进程名额。旅游结果包含结构化景点与美食卡；photo_worker.py 独立受限下载并压缩 Commons 照片，guide_visuals.py 转义内容生成卡片；最终结果及 media 在同一数据库事务与共享备份锁内保存。新组件不接收模型工具调用，不导入候选网站代码；生产上传目录是控制器新增的唯一写入路径。网站与旅游任务独立失败/取消，发布仅控制网站服务，不停止旅游子进程。

智能图文攻略统一为 template=auto，planning_summary+itinerary 明确自动规划思路和逐日顺路安排，服务端严格校验完整天数、候选数量、时段顺序与内容长度。guide_visuals.py 确定性渲染总览、路线和日程表；旧报告仍按原结构兼容，不改历史正文。


## 实际旅行任务与审核更新

`trip_workflows.py` 为当前旅行的当天调整、临行复核、归来整理和偏好建议提供严格响应结构与证据校验。上下文由管理员 API 从最新真实旅行生成，照片仅以用户说明作为证据。服务器只保存建议结果；管理员预览、选中并确认后才创建新计划、清单、私密足迹或个人偏好。新 schema 对旧表仅新增随记与旅行足迹关联。

需单独迁移的候选也先隔离测试；业务 API 与 feature_*.py 模块支持有确认记录的发布，数据库、依赖、系统工具和未知模块不进入此流程。封存版本生成管理员可下载的代码/测试审核包，仍从 root 封存目录发布，不从下载包或开发副本执行。审核包随旧候选清理。两个页面空闲不轮询，运行状态不含全文和代码差异。

CLI 运行元数据写入报告；缺少型号/推理强度则明确未知，独立环境不继承 root 模型配置。没有新增依赖或长期运行的模型进程。
